1,000건의 대용량 데이터셋에서 실시간 검색, 동적 정렬, 오프셋 vs 커서 페이징을 테스트합니다.

커서 모드는 ID 내림차순(id DESC)으로 고정되어 정렬 선택이 비활성화됩니다. 검색은 그대로 적용됩니다.

백엔드 & DB 파이프라인 검사기

프론트엔드 상태 변화에 따라 실제로 백엔드에 전송된 요청과 실행된 SQL을 모니터링합니다.

① 전송된 HTTP 요청 URL 0.00ms
GET /api/posts?page=1&limit=10&sort=latest
② 데이터베이스 실행 SQL (보안 파라미터 바인딩)
SELECT * FROM posts ORDER BY created_at DESC, id DESC LIMIT 10 OFFSET 0;
③ 백엔드 표준 Envelope JSON 응답
{ "items": [], "meta": {} }
💡 실무 엔지니어링 체크포인트:
• 검색창에 빠르게 타자를 칠 때 300ms 디바운스로 단 1회만 호출되는지 확인하세요.
• 새 검색어를 칠 때 이전 진행 중이던 비동기 fetch가 AbortController로 안전하게 취소됩니다.
• 주소창의 URLSearchParams가 동기화되어 뒤로 가기 및 새로고침 시에도 상태가 복원됩니다.
